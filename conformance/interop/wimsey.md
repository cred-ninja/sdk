## Cred signs a response, and wimsey's response profile verifies it: PASS

With `externalIdentity.responseSigning` holding Cred's own WIT (`spiffe://domain-b.example/cred/final-hop`), a request carrying `wimse-sign-response` got a signed `200`. A small Rust program (`scripts/hackathon/interop/wimsey/verify-response`) pinned to wimsey `56b0705` checked it with wimsey's `verify` under `wimse_response_profile`, `expected_req_nonce` set to the request's nonce, and the key from the response WIT's `cnf.jwk`. The result: OK, covering `@status`, `workload-identity-token`, `content-type`, `content-digest`, `@method;req`, `@path;req` and `@query;req`, and the Content-Digest matched the body. `wimsey wit verify` accepted Cred's WIT. Flipping one body byte makes the check fail (exit 1).
